# 自动化实现说明

本文件夹用于展示已经落地的数据处理实现：`自动化入库.py`、`字段说明.xlsx`、`数据质量规则.xlsx`和`requirements.txt`。

`自动化入库.py`按 Parquet 分片依次执行字段筛选、规则审查、错误处理、字段映射、类型转换、分表、MySQL 写入，并在入库后创建 Power BI 使用的视图和七组 SQL 初步分析结果。脚本默认只跑首个分片；加入 `--all` 后处理全部分片。

`字段说明.xlsx`记录分析层字段取舍；`数据质量规则.xlsx`保存业务规则、错误处理规则和字段映射。清洗逻辑读取这两份配置，规则与处理动作没有散落在多份脚本里。

原始 Parquet 体积较大，没有随交付包复制。复现时可把分片放在本文件夹下的 `原始数据` 文件夹，或设置环境变量 `NYC311_DATA_DIR` 指向本地数据目录。MySQL 主机、端口、用户和密码分别可通过 `NYC311_MYSQL_HOST`、`NYC311_MYSQL_PORT`、`NYC311_MYSQL_USER`、`NYC311_MYSQL_PASSWORD` 提供；密码缺失时脚本会交互输入。

主要依赖：pandas、pyarrow、openpyxl、SQLAlchemy、PyMySQL。七问 SQL 位于同一交付包的 `探索过程/生成初步分析结果.sql`，脚本使用相对路径读取。

## 运行前确认

运行前必须用 `NYC311_MYSQL_DATABASE` 显式指定目标数据库。脚本先检查分片存在、Parquet元数据有效、记录数非零、关键字段和配置文件齐全，再连接数据库。目标库已有项目结果表时默认停止；只有显式传入 `--replace-existing` 才允许重建。`--all` 仅扩大分片范围，不能代替重建授权。请使用独立测试库；重建并非原子操作，后续处理失败不会自动恢复旧表。

当前日期规则针对项目的 2026-09-07 历史快照。若重新获取更新数据，应先核对规则表及脚本的快照日期，再运行；不能直接把更新快照视为本报告的复现数据。直接打开已导入数据的 PBIX 不需要数据库。
